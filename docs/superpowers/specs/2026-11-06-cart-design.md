# ตะกร้าสินค้า (cart)

วันที่: 2026-11-06 · สถานะ: ทำตามคำสั่งของเจ้าของงาน ("ส่วนนายนะ josh ทำเรื่อง cart") มีการตัดสินใจระหว่างทางที่รอตรวจ (หัวข้อสุดท้าย)

ต่อจาก [ราคา lot และหน้าสินค้า](2026-11-06-shop-lot-pricing-and-storefront-design.md) หน้าสินค้าคืน `shopProductSkuId` ของแต่ละ SKU เพื่อให้ตะกร้าเรียกใช้

## ที่มา

ตะกร้าเดิม (`cart.t_cart`) ออกแบบก่อนมี lot และ SKU หลาย level: `sku_id` ว่างได้ และ unique ธรรมดา ซึ่งใช้ไม่ได้กับ soft delete เมื่อราคาและสต็อกย้ายไปอยู่ที่ lot ที่เปิดขาย ตะกร้าจึงต้องอ่านราคาจาก lot สดทุกครั้งแทนการเก็บราคา

## เป้าหมาย

- ลูกค้าเพิ่ม แก้จำนวน และลบสินค้าในตะกร้า ผ่านเส้นเดียว (upsert) และเส้น batch (ใช้ย้ายตะกร้าแขกเข้าตะกร้าของผู้ใช้ตอนล็อกอิน)
- อ่านตะกร้าแบบจัดกลุ่มตามร้าน พร้อมราคาปัจจุบัน สถานะของแต่ละบรรทัด และยอดรวม
- กันการเพิ่มเกินสต็อกของ lot ที่เปิดขาย

## ไม่ใช่เป้าหมาย

- การสร้างออเดอร์จากตะกร้า (checkout) ส่วนลด ภาษี ค่าส่ง และการตัดสต็อก เป็นของโดเมนออเดอร์
- การเก็บราคาหรือ lot ในตะกร้า
- ตะกร้าของผู้ไม่ล็อกอินฝั่งเซิร์ฟเวอร์ (ฝั่งแขกเก็บที่ client แล้วส่งผ่านเส้น batch ตอนล็อกอิน)
- "บันทึกไว้ซื้อทีหลัง" ตะกร้ามีแค่ ACTIVE กับ DELETED

## ผลงาน

- Schema: `cart.t_cart.sku_id` เป็น NOT NULL และเปลี่ยน unique เป็น partial unique index (migration `05`, schema doc, ER diagram ทั้ง 2 หน้า, แบบทดสอบ `db/tests/05-cart.test.sql`)
- Spec ใน `e-commerce/doc/api/cart/`: `01-upsert-cart-item`, `02-upsert-cart-item-batch`, `03-inquiry-cart`
- ตัวตรวจ `check_docs.py cart-spec`

## การตัดสินใจระหว่างทาง (รอเจ้าของงานตรวจ)

- R27 `cart.t_cart.sku_id` เป็น NOT NULL เพราะทุกสินค้ามี SKU อย่างน้อยหนึ่งตัว (SKU เริ่มต้นเมื่อไม่มี level) และราคาอยู่ใต้ SKU บรรทัดที่ไม่มี SKU จึงคิดราคาไม่ได้ `sales.t_order_item.sku_id` เปลี่ยนเป็น NOT NULL ตามด้วย (เจ้าของงานอนุมัติ) พร้อมแบบทดสอบ `db/tests/06-sales.test.sql` ส่วน `sales.t_order_item.lot_id` เปลี่ยนเป็น NOT NULL ด้วย (เจ้าของงานอนุมัติ) เพราะกำไรของรายการคิดจากต้นทุนของ lot
- R28 unique `(user_id, shop_id, product_id, sku_id)` เปลี่ยนเป็น partial unique index `WHERE row_status <> 'DELETED'` เพื่อให้เพิ่ม SKU เดิมกลับเข้าตะกร้าได้หลังลบ (กฎเดียวกับตารางอื่น)
- R29 ตะกร้าไม่เก็บราคาและไม่เก็บ lot ราคาอ่านจาก lot ที่เปิดขายตอนอ่านทุกครั้ง ดังนั้นลูกค้าเห็นราคาปัจจุบันเสมอ ไม่มี "ราคาเปลี่ยนจากตอนที่เพิ่ม"
- R30 หนึ่งผู้ใช้มีหนึ่งตะกร้า เก็บได้สูงสุด 100 บรรทัดที่ยังไม่ถูกลบ (ค่า config) เกินตอบ 409 (E10008) การอ่านตะกร้าจึงไม่มี paging
- R31 เพิ่ม SKU เดิมโดยไม่ส่ง `id` จะบวกจำนวนเข้าบรรทัดเดิม (merge, ตอบ 200) ส่ง `id` คือแทนที่จำนวน (update) ใน batch ห้ามมี SKU ซ้ำในรายการที่ไม่มี `id` (400)
- R32 `rowStatus` รับเฉพาะ ACTIVE และ DELETED (อย่างอื่น 400) Delete ตอบ 204 ตามข้อตกลง ตะกร้าไม่มี archive
- R33 ตอนเพิ่ม merge หรือแก้จำนวน ต้องไม่เกินจำนวนคงเหลือของ lot ที่เปิดขาย และ SKU ต้องเปิดขายอยู่ ไม่เช่นนั้น 409 (E10007) บรรทัดที่อยู่ในตะกร้าแล้วอาจเกินสต็อกภายหลังได้ การอ่านตะกร้าจะรายงาน
- R34 การอ่านตะกร้าจัดกลุ่มตามร้านและบอกสถานะของแต่ละบรรทัด 4 แบบ: AVAILABLE, QUANTITY_EXCEEDS_STOCK, OUT_OF_STOCK, UNAVAILABLE ยอดรวมนับเฉพาะ AVAILABLE ไม่รวมส่วนลด ภาษี ค่าส่ง
- R35 ผู้ใช้มาจาก access token เสมอ คำขอไม่มี `userId` บรรทัดของผู้ใช้อื่นถือว่าไม่พบ (404)
- R36 รหัส error ใหม่: E10007 (สต็อกไม่พอหรือสินค้าไม่เปิดขาย) และ E10008 (ตะกร้าเต็ม)
- R37 รูปที่แสดงในตะกร้าใช้กติกาเดียวกับหน้าสินค้า: รูปของค่าใน level ล่างสุดที่มีรูป ถ้าไม่มีใช้รูปแรกของสินค้า
